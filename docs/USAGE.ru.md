# Инструменты Jetson: руководство и профили плат

[English version](USAGE.en.md) · [Обзор проекта](../README.ru.md)

В руководстве описаны хостовая система Debian, развёртывание L4T, прошивка и добавление профилей плат.

## 1. Хостовая система и зависимости

Целевая хостовая система этого репозитория — **Debian GNU/Linux 13 (Trixie), x86_64**. Запускайте скрипты от обычного пользователя с рабочим доступом через `sudo`. Не запускайте всю подготовку от root: повышенные права запрашиваются только для необходимых операций. В примечаниях NVIDIA к Jetson Linux R36.5 перечислены Ubuntu 20.04/22.04 x86_64 как поддерживаемые хостовые системы, поэтому поддержка Debian здесь является сопровождаемым сообществом уровнем совместимости, а не сертификацией производителя ([примечания NVIDIA R36.5](https://docs.nvidia.com/jetson/archives/r36.5/ReleaseNotes/Jetson_Linux_Release_Notes_r36.5.pdf)).

Установите пакеты, используемые скриптами развёртывания и совместимости Debian:

```bash
sudo apt-get update
sudo apt-get install -y \
  git pv tar bzip2 sudo \
  abootimg xmlstarlet gdisk parted cpio gzip binutils \
  sshpass openssh-client
```

Если `sudo` ещё не установлен, сначала выполните `apt-get` от root (например, через `su -`), установите `sudo`, а затем используйте команду выше.

| Пакет Debian | Назначение |
| --- | --- |
| `git` | Клонирует репозиторий. Не нужен при получении проекта архивом исходников. |
| `pv` | Показывает прогресс распаковки в `setup_jetson.sh`. |
| `tar`, `bzip2` | Распаковывают релизные архивы NVIDIA `.tbz2`. |
| `sudo` | Запускает операции настройки L4T, привилегированные файловые команды и прошивку. |
| `abootimg`, `xmlstarlet`, `gdisk`, `parted`, `cpio`, `gzip` | Утилиты хоста, проверяемые `setup_debian.sh` для генерации recovery-образа L4T. Команда `sgdisk` входит в пакет `gdisk`. |
| `binutils` | Предоставляет команду `strings`, используемую инструментами L4T. |
| `sshpass`, `openssh-client` | SSH-утилиты, необходимые скриптам L4T; `ssh-keygen` входит в `openssh-client`. |

`setup_debian.sh` проверит наличие и установит недостающие пакеты для исправления L4T из этого списка. Базовые утилиты `bash`, `awk`, `sed`, `grep`, `find`, `install`, `md5sum` и `mount` входят в обычную установку Debian. При ошибке стороннего APT-репозитория скрипт выдаст предупреждение и всё равно попробует установить пакеты из доступных индексов.

### Необязательный QEMU chroot

Для необязательного chroot нужен пакет `qemu-user-static`. Если этап выбран, а исполняемый файл `qemu-aarch64-static` отсутствует, `setup_jetson.sh` установит пакет автоматически. Чтобы пропустить этап, укажите `--skip-qemu`.

### Необязательная сборка для подавления предупреждений OP-TEE

Пакеты нужны только для `b_conf/suppress_uefi_auth_warnings.sh`:

```bash
sudo apt-get install -y make python3 device-tree-compiler patch ripgrep binutils
```

Также понадобится кросс-компилятор NVIDIA AArch64 Buildroot: файл
`aarch64-buildroot-linux-gnu-gcc` должен находиться в каталоге
`$CROSS_COMPILE_AARCH64_PATH/bin/`. Он не устанавливается указанной командой
и не входит в этот репозиторий.

## 2. Получение файлов релиза NVIDIA

Скачайте пакет L4T Driver Package и Sample Root Filesystem **одного и того же релиза L4T**. Поместите оба архива `.tbz2` в каталог со скриптом `setup_jetson.sh`:

```text
Jetson_Linux_<L4T-релиз>_aarch64.tbz2
Tegra_Linux_Sample-Root-Filesystem_<L4T-релиз>_aarch64.tbz2
```

Например, в истории этого проекта JetPack 6.2.3 использует L4T R36.5.2:

```text
Jetson_Linux_R36.5.2_aarch64.tbz2
Tegra_Linux_Sample-Root-Filesystem_R36.5.2_aarch64.tbz2
```

Используйте имена файлов, предоставленные NVIDIA для целевого релиза. Скрипты не скачивают архивы самостоятельно. Архив `public_sources.tbz2` необязателен и будет распакован, только если положить его рядом со скриптом именно под этим именем.

## 3. Развёртывание дерева L4T

Запускайте из корня репозитория. Пример явно выбирает JetPack 6.2.3, соответствующий релиз архива L4T и профиль AGX Orin devkit без чтения EEPROM carrier-платы:

```bash
./setup_jetson.sh \
  --jetpack-version 6.2.3 \
  --version R36.5.2 \
  --board jetson-agx-orin-devkit-noeeprom \
  --skip-qemu
```

Параметры версий имеют разное назначение:

- `--version` задаёт токен релиза L4T, например `R36.5.2`, который должен совпадать с именами архивов NVIDIA.
- `--jetpack-version` выбирает семейство профиля, например `6.2.3`.

Если не задавать `--version`, выбирается самая новая согласованная пара архивов L4T и rootfs. Если не задавать `--jetpack-version`, используется имя каталога, в котором лежит `setup_jetson.sh`. Если репозиторий склонирован в каталог общего назначения, например `jp_tools`, передавайте `--jetpack-version` явно.

По умолчанию развёртывание выполняется в `./Linux_for_Tegra`; каталог можно изменить через `--dir PATH`. Скрипт распаковывает L4T и rootfs, запускает `apply_binaries.sh`, создаёт пользователя, копирует `root_fs/`, при наличии распаковывает публичные исходники, устанавливает выбранный пакет `b_conf` и применяет исправления для Debian.

Если `Linux_for_Tegra` уже существует, интерактивный режим предложит использовать его повторно или удалить. Параметр `--force` удаляет каталог и выполняет развёртывание из архивов заново. Это удаляет всё содержимое указанного каталога развёртывания; заранее сохраните нужные файлы. В пакетном режиме (`-y`) существующее дерево будет использовано, если не указан `--force`.

Без `--skip-qemu` в конце скрипт спросит, нужно ли войти в QEMU chroot. В тихом режиме (`-y`) подтверждения считаются принятыми, поэтому для автоматического развёртывания без запуска chroot указывайте оба параметра: `-y --skip-qemu`.

### Пользователь Jetson и вход root через UART

Сначала скрипт запускает NVIDIA `tools/l4t_create_default_user.sh`, затем настраивает UART-вход. По умолчанию создаётся drop-in systemd getty, включающий вход root без пароля через UART `ttyTCU0` для отладки. Чтобы отключить эту настройку, добавьте параметр к команде развёртывания, например:

```bash
./setup_jetson.sh --jetpack-version 6.2.3 --version R36.5.2 \
  --board jetson-agx-orin-devkit-noeeprom --skip-qemu --no-root-uart-login
```

Параметр применяется после создания пользователя и необязательного QEMU-этапа. Вход root без пароля предназначен для контролируемой отладки; на эксплуатируемых устройствах отключите его.

## 4. Подготовка и прошивка платы

Выведите профили, подходящие для выбранной версии JetPack:

```bash
./b_conf/flash_jetson.sh --list --jetpack-version 6.2.3
```

Изучите `COMPATIBILITY.md` выбранного профиля. Для предварительного просмотра, который покажет файлы и команды прошивки, не копируя их и не записывая данные на устройство, выполните:

```bash
./b_conf/flash_jetson.sh \
  --board jetson-agx-orin-devkit-noeeprom \
  --mode full \
  --jetpack-version 6.2.3 \
  --dry-run
```

Переведите Jetson в режим USB Recovery и подключите к хосту, затем запустите команду без `--dry-run`. Скрипт установит файлы выбранного профиля и запросит подтверждение перед записью разделов устройства.

В руководстве релиза NVIDIA также описан запуск `sudo tools/l4t_flash_prerequisites.sh` из распакованного BSP перед прошивкой. Содержимое этого помощника зависит от релиза; данный проект устанавливает пакеты и исправления для Debian, описанные выше ([руководство NVIDIA по прошивке](https://docs.nvidia.com/jetson/archives/r36.5/DeveloperGuide/SD/FlashingSupport.html)).

Режимы прошивки:

| Режим | Операция |
| --- | --- |
| `full` | Запускает `sudo ./flash.sh <плата> <корневое-устройство>`. |
| `dtb` | Записывает `A_kernel-dtb`, затем `B_kernel-dtb`. |
| `rootfs` | Записывает только раздел `APP`. |

Корневое устройство по умолчанию — `mmcblk0p1`. Если конфигурация платы требует другого, задайте его через `--rootdev DEVICE`. Примеры:

```bash
./b_conf/flash_jetson.sh --board jetson-agx-orin-devkit-noeeprom --mode full --jetpack-version 6.2.3
./b_conf/flash_jetson.sh --board jetson-agx-orin-devkit-noeeprom --mode dtb --jetpack-version 6.2.3
./b_conf/flash_jetson.sh --board jetson-agx-orin-devkit-noeeprom --mode rootfs --jetpack-version 6.2.3
```

Параметр `--yes` пропускает интерактивное подтверждение записи и предназначен для контролируемого пакетного запуска. Скрипт также откажется перезаписать существующий файл BSP, если в выбранном профиле по тому же пути лежат другие данные. Разберитесь с конфликтом или используйте чистое дерево L4T; не перезаписывайте файлы производителя вслепую.

Чтобы вызвать утилиту NVIDIA напрямую после подготовки профиля:

```bash
cd Linux_for_Tegra
sudo ./flash.sh jetson-agx-orin-devkit-noeeprom mmcblk0p1
```

Для профиля IDS 10G/4 Ethernet на соответствующем BSP JetPack 6.2.x:

```bash
cd Linux_for_Tegra
sudo ./flash.sh jetson-agx-orin-10g_4eth_pci_nvme_dp mmcblk0p1
```

Последний профиль проверен только на исходниках JetPack 6.2.3, указанных в его журнале. Перед использованием с другим выпуском 6.2.x прочитайте журнал совместимости.

## 5. Добавление профиля платы

Выбирайте самый узкий селектор, который соответствует фактической проверке:

```text
b_conf/
  common/<профиль>/                 # предполагается совместимость между семействами JetPack
  5.1.7/<профиль>/                  # один точный релиз JetPack
  6.2.x/<профиль>/                 # предполагается совместимость с семейством 6.2
  6.x/<профиль>/                   # предполагается совместимость со всеми релизами JetPack 6
  7.x/<профиль>/                   # предполагается совместимость со всеми релизами JetPack 7
```

Селектор проверяет каталоги в порядке: `<major>.<minor>.<patch>`, `<major>.<minor>.x`, `<major>.x`, `common`. Например, для JetPack `6.2.3` проверяются `6.2.3/<профиль>`, `6.2.x/<профиль>`, `6.x/<профиль>`, затем `common/<профиль>`.

Каждый пакет должен быть полным; файлы из нескольких пакетов не объединяются. Минимальная рекомендуемая структура:

```text
b_conf/<селектор>/<профиль>/
  COMPATIBILITY.md
  Linux_for_Tegra/
    <профиль>.conf
    ... пользовательские BCT, pinmux, GPIO, DTB и другие нужные файлы ...
```

Рекомендуемый порядок работы:

1. Начните с работающего BSP производителя для точного релиза JetPack и найдите подходящую базовую конфигурацию платы. Не изменяйте файлы NVIDIA; добавьте новый `<профиль>.conf` с уникальным именем, укажите в нём базовый профиль и переопределите только необходимые параметры платы.
2. Разместите все пользовательские файлы, на которые ссылается конфигурация, внутри пакета по соответствующим путям `Linux_for_Tegra/`. Не копируйте файлы NVIDIA, уже поставляемые целевым BSP.
3. Добавьте `COMPATIBILITY.md`. Запишите ревизию платы/carrier, предполагаемые версии JetPack и L4T, источник конфигурации, предварительные условия, точные выполненные проверки и их результаты, а также незавершённые проверки. Различайте анализ исходников, компиляцию DTB, пробный запуск прошивки и реальную прошивку с загрузкой платы.
4. Если добавляются бинарные DTB, опишите воспроизводимую сборку и исходники, добавьте SHA-256. Не заявляйте о проверке семейства версий, если проверили только один релиз.
5. Проверьте результат селектора и shell-тесты:

   ```bash
   ./b_conf/flash_jetson.sh --list --jetpack-version 6.2.3
   bash tests/x86/test_b_conf_selector.sh
   bash tests/x86/test_jetson_flasher.sh
   ```

6. Выполните `--dry-run`, проверьте выбранный пакет и его файлы, затем проверьте профиль на соответствующем BSP до прошивки физической платы. После проверки обновите журнал совместимости.

Установщик добавляет только отсутствующие файлы. Если по целевому пути уже существует файл с другим содержимым, установка останавливается, а файл производителя остаётся нетронутым. Структурируйте пакеты так, чтобы селектор не выбирал несовместимые данные молча.

## 6. Необязательное подавление предупреждений OP-TEE

Патч меняет две записи о тестовом ключе с `IMSG` на `DMSG`; при стандартном уровне логирования T234 они подавляются. Сообщения об ошибках сохраняются. Это меняет только логирование и не включает защиту UEFI-переменных.

Соберите образ-кандидат без установки:

```bash
export CROSS_COMPILE_AARCH64_PATH=/путь/к/nvidia/aarch64-buildroot-toolchain
./b_conf/suppress_uefi_auth_warnings.sh --build
```

Утилита извлекает только архив исходников OP-TEE текущего BSP, применяет патч во временном каталоге, собирает OP-TEE и проверяет строки предупреждений/ошибок. Параметр `--install` повторно собирает образ, проверяет результат, запрашивает подтверждение перед заменой и сохраняет резервную копию:

```bash
sudo --preserve-env=CROSS_COMPILE_AARCH64_PATH \
  ./b_conf/suppress_uefi_auth_warnings.sh --install
```

Перед заменой установщик запросит подтверждение, а исходный файл сохранит как `tos-optee_t234.img.before-quiet-uefi-warnings`. Восстановить его можно командой:

```bash
sudo ./b_conf/suppress_uefi_auth_warnings.sh --restore
```

После установки прошейте устройство заново. До прошивки нового образа TOS изменение на самой плате не действует. Успешную сборку и загрузку на железе следует проверять отдельно.

## 7. Диагностика и проверка

- **Профиль не найден:** укажите правильный `--jetpack-version`, проверьте имя каталога селектора и наличие обязательного файла `<профиль>.conf`.
- **Не найдена пара архивов:** проверьте, что оба архива NVIDIA используют одинаковую версию L4T и лежат рядом с `setup_jetson.sh`.
- **Конфликт профиля:** проверьте различающийся файл назначения BSP. Для повторного развёртывания используйте чистое дерево или намеренно согласуйте пользовательский файл; установщик защищает различающиеся файлы производителя.
- **Прошивка не видит плату:** проверьте USB Recovery, кабель передачи данных, права на хосте, имя платы и корневое устройство.
- **Ошибка патчей хоста:** изучите вывод установки пакетов и первую упавшую команду. `setup_debian.sh` изменяет recovery-image скрипт распакованного BSP, а для пользовательского профиля IDS 10G — ещё и конфигурацию RCM/BCT.
- **Ошибка сборки OP-TEE:** проверьте, что по указанному пути NVIDIA toolchain доступен ожидаемый кросс-компилятор и установлены `device-tree-compiler`, `make`, Python 3, `patch` и `ripgrep`.

Shell-тесты x86 проверяют выбор профиля и ограниченное формирование команд прошивки; они не заменяют проверку каждого BSP производителя или тест прошивки/загрузки на плате.
